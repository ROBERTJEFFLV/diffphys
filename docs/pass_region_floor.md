# 穿点球的0.1m半径下限

2026-10-28，按用户要求，当前三点任务统一使用：

`穿点球半径 = max(region_radius_arms × L, 0.1m)`。

默认`region_radius_arms=2`，所以小机型的2L不足0.1m时使用0.1m，大机型继续使用2L。这是物理半径下限，没有将位置或损失改为无量纲形式。

`plane_tasks.pass_region_radius` 是公共计算入口。平面点位采样、原随机中点采样、任务准备均调用它。得到的`GoalState.radius`继续用于Actor第69维输入、首次入球/出球切点、平面有效圆盘、计分和回放导出；没有只改图上画出的球。采样间距及完整球围栏检查继续使用实际半径，容不下时仍明确报错。

中点中心位置容差仍为0.1m；速率下限仍为1.5m/s，方向仍朝终点且垂直实际机体z轴。Actor、原loss公式、物理、噪声、128组及原生分组反传/裁剪保持。被撤除的数值缩放和Adam候选验收没有恢复。

任务版本加入`min-region-radius-0p1m-v1`标记。旧三点检查点按旧源评估；新规则不能冒充旧任务的精确续训，可显式只导入Actor权重建立新运行。旧检查点、哈希和历史回放没有被改写；播放器优先读取回放自身记录的实际半径。

回归包含FP32/FP64、平面和原随机姿态任务、小/大机型、Actor半径输入，以及原0.086m掠过案例的实际入球、出球和硬PASS计分。它验证几何/代码行为，不代表策略已学会；本轮不启动训练。

其他调查结论保存在 `reports/root_cause_20261028/report.md`，其原2L数据是修改前的历史证据。这次只修正半径过小的问题，首次事件的计分切换、绕行布局、不可恢复初态和微调控制能力退化仍需分别处理。
