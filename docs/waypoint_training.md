# 固定点机动训练：事件约束、完整物理 BPTT 与硬切点梯度

本实现从 `Agile-Flight-training@9187097` 改造。原三维四旋翼、电机迟滞、测量延迟、硬边界以及 CUDA 单步前向/反向编译保持原源码。它不导入参考轨迹，也不把独立的二维 IPOPT 规划器冒充成神经网络训练。

## 1. 生效入口与固定点命令

```bash
python tools/train_response_control.py @configs/agile_flight.args \
  --init-checkpoint /absolute/path/hover.pt \
  --work-dir runs/waypoints/from_hover
```

`--task agile` 现在路由到 `diffphys/waypoint_training.py`；同义直接入口为 `tools/train_waypoint_control.py`。配置为 `configs/waypoint_flight.json`。旧的 `agile_objective.py` / `agile_mission.py` / `agile_flight.json` 保留供历史工具使用，不在新的 agile 训练路径中。

旧 hover CLI 原文移到 `tools/_hover_training_cli.py`；主入口验证其 Git blob 哈希再调用。`--task hover` 保留原行为。旧协议 checkpoint 的评估默认走原入口；新 checkpoint 可自动识别。不要把旧三点 run 当作新目标的精确续训。

控制每 0.01 秒执行一次，最多 500 步：

- 出生于点1，保留原非零初速；原零初速行用独立随机流补入每轴 Uniform[-2.5,2.5] m/s，历史速度同步。
- 用**测量位置**判断当前点半径 0.1 m，进入后下一次电机命令使用下一固定点。不等姿态/速度达标，不重置 GRU。
- 出生在点1范围内时，第一次动作已经面向点2。点3永久锁定；偏离后不退回点2。
- 目标包含当前点、下一固定点、终点、尚未完成的中点姿态/穿越方向，以及终点/穿越待完成标记。没有时间进度、倒计时或移动参考。
- 入球先于过中心。即使当前命令已经是点3，穿越监督仍保留中点姿态要求，直到完成几何穿越；目标包在离开指定穿越带后改为水平姿态和零速度。姿态从不阻止命令切换。

默认请求105度，绝不根据机型能力偷偷降低角度、缩短路径或挑掉弱机型。出生水平、零角速度，电机设为无外力平衡，前一条公开命令仍为零占位，不能泄露隐藏电机状态。只关闭外力；保留原测量噪声和10–30 ms速度延迟。

## 2. 区域与任务语义

固定几何沿用半跨度0.7B、弯曲量0.38B，B是原来的每轴位置限制。不是重新生成要跟踪的曲线。所有点必须位于原边界内，且进场/穿越/制动区域互不重叠；无效几何明确报错。

默认不减速带半宽 `min(0.5 m, 0.4 * half_span)`，姿态带半宽0.1 m。前者是**固定、公开的几何规则**，避免小飞机的终点仍处于禁减速区；不是训练课程。日志/回放记录每架飞机的实际半宽。它与独立规划验证中固定0.5 m的条件并非完全相同，不能直接移用成功率。

穿越方向 n 由固定任务给出，不能通过瞬时速度重新定义：

```
中心平面：n·(p-p2)=0，第一次正向横穿
过平面位置：|p-p2| <= 0.1 m
目标姿态：完整 SO(3) 相对误差 <= 1 degree
正向速度：n·v >= 2 m/s（默认，显式任务参数）
穿越带内：v·a >= 0（总速率不下降）
```

速率不下降与前向速度不下降不同；本实现要求前者和正向速度下限，没有声称二者等价。在整个姿态平面带内检查姿态，覆盖0.1 m球，且比只在中心检查更强。离开穿越带后允许制动。相同平面带再次进入时约束再次生效。

终点每个约束在H时刻都无条件计分：位置、零速度、水平姿态、零角速度、真实线加速度、角加速度及电机变化率。没进入中点不免除末端义务。默认容差见JSON；终点控制目标是固定点和停止，容差只是任务判定标准。没有固定一秒保持窗口。

完成时间为最后一次离开**全部终点容差集合**之后的采样时刻，且须先完成中点命令入球和真实平面穿越。未完成按5 s截尾并保留违反量。不因早停、漏点而少记账。有限H只能检查已展开的未来，不能证明无限时间稳定。

## 3. 真正进入优化器的目标

每场景每条件计算无量纲不等式 `g[n,j] <= 0`。穿越缺失时保留 `1 + 最近位置误差 / 0.1m` 恢复残差，并在最近状态计算姿态/速度；未穿越不会被当作姿态成功。没有高斯距离加权姿态、取消固定的5倍/10倍权重竞争。

```
L_n = T_n/5 + sum_j ((relu(mu_nj + rho*g_nj)^2 - mu_nj^2)/(2*rho))
L = mean_n L_n
mu_nj <- relu(mu_nj + rho*g_nj)
```

所有样本、每个条件先分别计算，再平均；不会把正负违反量先平均掉。姿态用完整旋转矩阵弦长除以角度容差的对应弦长，避免 acos 的端点数值问题；相对180度的切向梯度仍可退化，不宣称全局无奇点。

固定场景银行32次参数更新，每8次更新一次乘子；4次乘子更新后换银行，**新场景的乘子从零开始**。每次乘子更新基于刚更新后的Actor。下一银行在CPU预取，不重采样当前银行、改变任务或使用成功率晋级。乘子与银行索引/完整哈希随checkpoint保存。

这是约束学习算法，不是有限迭代约束必然成立的保证。`all_constraints_fraction` 才是独立任务诊断之一；AL数值随乘子变化，不能直接横比不同外层迭代的标量大小。

## 4. 梯度、硬切点与数值事件

中心处的连续分支：原四旋翼完整H500 BPTT；原生GRU/Linear；物理仍是CUDA上的原 `make_simulator()`。Time Decay必须为0。

平面穿越：在第一次正向变号的原控制区间内二分求根，用**原RK4函数的分数步长**重算状态，而不是线性插值姿态。隐函数导数包含事件时刻敏感度。分数步是监督工具，不推进真实物理/控制器/测量时钟；原生产RK4代码没有修改。擦边/非横穿事件明确标记无效，不假造无限导数。

硬命令切点、事件区间选择、最大违反节点与完成时间都是分段/不连续操作。使用相同银行、相同噪声、相同冻结乘子的成对完整前向：

```
g = gp + mean_m [((L(theta+sigma*z)-L(theta-sigma*z))/(2*sigma) - gp·z)*z]
z ~ Normal(0,I), sigma=0.001（默认）
```

`gp`是与本组随机方向独立的中心物理梯度。方向不能归一化。原估计器针对高斯平滑的完整硬程序目标，不是原跳变函数不存在的普通导数。全局范数裁剪、Adam之后也不再称作同一个无偏估计。

**有意改变：**新的 agile 任务使用均匀场景标量的原始BPTT，不再对物理组单独裁剪/重加权，再把它当成这个AL目标的精确梯度。原 `response_groups.py`、`response_grad_probe.py` 均保留且不改，hover仍使用它们；新链不调用它们。物理 coverage128 场景覆盖仍保留，与梯度重加权是不同的事情。

默认4个扰动方向，需要**额外8次完整前向**，无额外反向；乘子更新还需一次更新后前向。这会增加训练成本，尚未证明比原方案更快或低方差。默认TRAIN改为4×128=512场景，不是旧的3072；显存与耗时需重新测量。CPU只是数值参考，默认物理不compile；CUDA才使用原单步编译后端，编译错误不静默回退。

默认约束监督每5 ms采样一次（原步端点加原核半步）；这**不是连续时间安全证书**。原10 ms命令采样仍可能漏检短暂入球，训练将其计为命令未到达，不偷偷提高Actor频率。第一次过平面仍以原步端点正向变号定位：单步内多次穿越属于需密集复核的情况，不冒称全部连续事件均被捕获。

## 5. checkpoint、续训、评估与回放

同一源码和配置精确续训：

```bash
python tools/train_response_control.py @configs/agile_flight.args \
  --resume runs/waypoints/from_hover/checkpoint.pt \
  --work-dir runs/waypoints/from_hover --updates 200
```

更换目标、数值设置或源码使用新目录和 `--init-checkpoint`，不改checkpoint哈希绕过检查。悬停权重输入矩阵16→36补零，其余全部参数复制并继续训练，Adam全新。输出包含完整Actor、任务配置和训练状态；加载不再查询原 `.pt` 路径。新旧目标包同维但语义不同，由独立schema/goal_convention区分，不能混用旧部署包装器。

```bash
python tools/train_response_control.py --mode evaluate --device cuda \
  --checkpoint runs/waypoints/from_hover/checkpoint.pt \
  --eval-split test --eval-scenarios 32 \
  --verify-audit-substeps 10 --replay-out runs/waypoints/test_replay.npz
```

评估使用checkpoint的目标/物理时域，乘子为零，另报每个约束违反量。`--verify-audit-substeps 10`仅提高约束检查密度至1 ms，不改变100 Hz控制，不是重新训练。NPZ包含状态、动作、当前点索引、事件时间/姿态/速度、带宽、原始违反量。失败事件的时间字段可能是最近接近的恢复样本时间，须结合`event_crossed`读取。

部署调用 `load_policy(checkpoint)` 和 `WaypointController`，提供同协议测量22维以及固定任务。公共controller不是安全监督器，不执行训练中的物理求根/AL/随机扰动。真实部署仍需要独立验证。
